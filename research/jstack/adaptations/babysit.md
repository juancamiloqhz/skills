## Preserved source limits

The source tests deliberately accept `UNKNOWN` merge states and treat `BLOCKED` as CI refusal only when the head rollup is `ERROR` or `FAILURE`. A pending `Code Review Gate` is excluded from pending CI, and `REVIEW_REQUIRED` is not a code blocker. Therefore `READY` is a watcher classification, not a blanket assertion that all human or forge permissions are satisfied. The operational procedure reports those qualifications and requires current evidence before claiming readiness. A redesign of that truth table needs its own decision.

The original review-thread read capped at 100. The [pagination update](../evaluations/watcher-pagination/README.md) now reads every page and counts Bugbot passes across resolved and unresolved threads before selecting blockers. It also classifies the named owner-approval gate's `ACTION_REQUIRED` state separately from failing CI. First-comment interpretation remains, commit history caps at 50, and connected-stack discovery caps at 300 open PRs. Check-rollup fallback is paginated. Empty check results fail closed, including repositories with no check runs. No installation or readiness claim should disguise these limitations. The source's stack-wide tier ordering can report an upper conflict before frontier CI; the playbook still prohibits unauthorized upper fixes.

The [evaluation](../evaluations/babysit/README.md) and [complete source comparison](../evaluations/babysit/source-comparison.json) separate preserved behavior, T3 adaptations and remaining live tests. Prior entrypoint and Opening a PR differences remain accounted for in their existing adaptation records.
