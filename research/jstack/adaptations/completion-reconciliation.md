# Completion reconciliation contract

Source: `pstack/skills/poteto-mode/playbooks/orchestrate.md`, especially Queue and drain, Verification, and Liveness and failure, at `11713c683fe4add4fd403ea880580abbc9e0875f`. Pstack assigns classification and acceptance to the coordinator. Keep that boundary. The existing CLI can record or replace a verdict but does not decide whether its caller should accept a worker's claim. This change adds the T3-specific instructions to the existing runtime reference; it adds no automatic classifier, task database, store schema or executable command. The full Orchestrate procedure remains unavailable, with 22 playbooks shipped.

| Upstream behavior | Necessary T3/runtime detail | Evidence and limit |
| --- | --- | --- |
| Classify completions at drain points and account for every child. | Bind unit/role/current attempt to the actual task ID and original run ID in existing dispatch records. Inspect status before accepting a notice. | Fixture cases reject an unassigned run and a superseded attempt. Real T3 identity recovery is not tested. |
| Read status without resuming an agent; reconcile late zombies. | Distinguish original `childRunId`/`summary` from later `latestTerminal*` fields. Check `workState`, pending child runs and pending questions. | Matches the live injected `task_status` tool contract. A modeled completed turn with live nested work remains unresolved. |
| Classify every pointer before updating status. | Recognize repeats by task/run identity and preserved result reference or digest; reconcile already-applied changes before replay. | Both paired runs account for all pointers while applying a repeated result only once. CLI push still preserves duplicates. |
| Verify the current PR/head; a verifier overrides a worker at the same key. | Recover roles and round order from dispatch evidence, compare actual artifacts, then read ledger provenance before writing. Keep stale evidence under its original SHA. | Modeled worker success does not overwrite an independent verifier failure. A later terminal summary does not re-label an original old-head report. |
| Drain, classify, update tables, render status. | Use the previously implemented claim/ack handoff, save a complete receipt, and persist blockers with next actions before acknowledging unresolved notices. | Actual CLI store writes and receipt hashes are checked. Acknowledgement is not completion of the underlying task. |
| Reconcile agents after restart. | Re-read standing orders, ownership and status; establish quiescence before replacement rather than assuming local or remote child survival. | The evaluation exercises saved batch processing only, not a provider restart or actual cancellation. |

The additional section applies when using `orch` for resumable completion handling. It does not impose a persistent program store on ordinary short tasks. Existing fresh-child, workspace, model selection, publication and authorization rules remain unchanged. Native children need equivalent observed identity and liveness evidence; T3 fields are not invented for a native tool.

The tool contract was inspected from this session's live MCP catalog. It says `childRunId` identifies the original delegated run, `workState` distinguishes live nested work, original summaries remain stable, and `latestTerminal*` describes later results. This assessment does not call old unrelated tasks or claim live T3 recovery. See the [bounded evaluation and usage](../evaluations/completion-reconciliation/README.md).
