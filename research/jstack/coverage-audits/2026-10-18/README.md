# Complete pstack coverage audit

Jstack contains the 23 Juan-mode procedures and 24 standalone principles, but it is not a complete or current port of pstack. This audit accounts for the whole source package, including components outside the main skill list. Recommendations are a proposed backlog, not implementation approval or evidence of runtime parity.

## Why the previous milestone was incomplete

The [roadmap](../../roadmap.md) explicitly scoped the earlier implementation to all 23 poteto-mode playbooks and their dependencies, not every pstack skill. Thus the older nine omissions were scope gaps, not assessed incompatibilities. Later upstream additions and changes also outpaced the pinned implementation. The [installation checker](../../evaluations/installation-readiness/README.md) compares installed bytes with jstack's own packages; a result of 45 matching packages says nothing about missing upstream features.

The user reports matching installations on Orbit and omarchy-mac. That establishes the reported file check on those roots, not provider discovery, dependency calls, complete upstream coverage or workflow correctness.

Two concrete tool gaps can be addressed without choosing a new product policy:

- The plan checker still toggles on triple backticks. Current upstream tracks fence character, length, indentation and closing suffix, so nested examples and tilde fences do not become false plan headings. Port the new five-case tests and rerun the local plan reproducer.
- The watcher still reads only the first 100 review threads. Current upstream reads all pages before counting Bugbot passes and unresolved findings, and treats the specific completed owner-approval gate with `ACTION_REQUIRED` consistently with its pending form. Test a late unresolved thread, cross-page pass counts, resolved later threads, unrelated failed gates and query failures. Also test missing/repeated cursors: upstream's current loop is not itself proof against malformed pagination.

Autopilot's changes are larger. Current source uses a full swarm at code-ready and for substantial new behavior, but a single independent verifier for rebases/conflict fixes/minor changes; every new head still needs CI and patch identity checks. It stores owner identities/trails at the root, distinguishes waiting questions from stalls, pins leases to the last owned push, classifies lockfile/caller/config drift, holds after a third preparation rebase, broadens countersigning to any weakened gate, and routes updates through Ketchup. Stack now inherits Full with four overrides, including root-only topology changes and frozen chain writes during landing. Local files retain the older cadence/structure. Test minor versus major changes, stale-head verdicts, lockfile/caller merge-result proof, unexpected pushes, waiting questions, root-record recovery and landing holds. Preserve T3 stop-or-isolate rules so replacing an agent cannot create two live writers in one checkout.

Shipping now permits genuinely independent PRs above a gap only after moving them to trunk and obtaining fresh verification. It requires actual merged state with trunk as base and moving the immediate child after each merge. Local already checks current head/base, frozen queues and actual merge state, but does not implement the entire new sequence. Verify a three-link squash chain, queued-but-not-merged result, unexpected parent/base, immediate-child retargeting, fresh verdict after extraction and topology mutation during landing.

Current Orchestrate uses automatic chain discovery and local Git heads. Jstack's required explicit PR scope checks API identities against published refs, ancestry and repeated reads before replacing a frontier. Its pending inbox manifest/digest/ack protocol also survives interruption where upstream still drains destructively. **Keep these documented safeguards.** Origin and automatic discovery can be assessed independently; they must not silently widen authorized scope. Test detached/trunk checkouts, multiple children, deleted/changed remote refs, malformed/draft/closed chains and prior-state preservation before extending support. Upstream cleanup still has whitespace-path, untracked-content and PR-state assumptions already corrected locally. Preserve those corrections, manual dependencies and actual user authority during all updates.

## Proposed implementation order and decision points

This is a complete coverage inventory and proposed backlog. The recorded delivery target remains the 23 playbooks and their dependencies. The audit does not expand that target or approve any proposed implementation. Keep the missing components visible so the user can choose a broader target or individual additions without losing the assessment.

1. **Correct current maintenance and bundled-tool gaps.** Expand the four external watch paths, add a focused current-doc check, update watcher pagination/owner-gate handling and plan-fence parsing with behavioral fixtures. These are independent small changes; no model decision is required.
2. **Bring existing workflow contracts forward.** If the user reopens Ketchup adoption, port Bro and Ketchup before their new callers. Reconcile autopilot/plan/Shipping together with current-head and writer-isolation cases. Update principle leaves/summaries, verifier startup, investigation prompts and TypeScript examples against this frozen revision while retaining documented local fixes.
3. **Complete missing standalone entrypoints and user documentation.** Port In your own words, Sharpen, Blast radius, Teach, Correct and formal verification in reviewable units. Adapt Recall and Automate me with scoped history proof. Build the help entrypoint and guide against the actual shipped catalog, keeping missing capabilities explicit.
4. **Resolve scope and integration choices with concrete designs.** Decide whether to expand the recorded delivery target or select individual additions, including reopening the Ketchup and Poteto-help dispositions. Decide whether exact saved effort remains the policy; whether Unslop stays a separately installed prerequisite; and whether additional Origin/discovery, plugin distribution, Make bot UI and Benny support belong in the next implementation group.
