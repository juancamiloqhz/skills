# Arena evaluation

Three cases exercise the standalone Arena source with separately copied setup-jstack dependencies and temporary model maps. The [results](results.json) preserve evaluated source hashes, task identities, host timing, candidate and judge artifacts, final synthesis and failure outcomes. Local raw evidence at `/tmp/jstack-arena-uyu9daca` may expire. No skills were installed and the user's global configuration remained unchanged.

## Executed cases

The successful case requested a design-only companion to a synthetic batch-delivery API. Two configured inherited runner seats produced independent proposals using fresh T3 task contexts and a common brief. Exactly one of two inherited judge alternatives ran after both candidates completed. The parent independently inspected the candidate briefs and host run timing, then read both proposals, rationales, judge report and final synthesis.

The judge and coordinator selected candidate A, but identified a usage example that could cause a caller to execute delivery twice. The final design integrated B's explicit alternative-call guidance and replay warning while retaining A's smaller interface. Original candidates remained unchanged. Verification traced caller usage, retry counts, uncertain delivery effects, partial results and ownership against the source. Proposed implementation tests were not executed because the requested artifact was a design.

Failure A provided one configured runner. Failure B provided two runners but required a different-family judge while both judge alternatives inherited the coordinator's exact model. Both resolved against live capabilities and stopped in Frame without child dispatch, synthesized designs, invented seats or settings changes. They shared evaluator context but used separate resolutions and output directories.

The parent verified the two terminal coordinator tasks, three nested completed host runs, candidate hashes, evaluated skill hashes and all baseline input hashes. Both failure scenarios returned incomplete workflow outcomes, as expected. One catalog-refresh patch failed before writing; the evaluator recovered by saving the refreshed catalog under a distinct owned path and resolving the judge before dispatch. Temporary catalogs were removed.

## Limits

All executed roles used inherited Codex. Candidate writers ran serially. Fresh prompt-only contexts and withheld scoring instructions were checked in dispatch briefs; this is not filesystem access isolation or proof that artifact style cannot reveal authorship. The coordinator retained the complete role/config evidence, but no full-host read audit was performed.

Successful different-family judging, candidate dropouts, reframing, the architect runner override, code worktrees, other providers, installation and future playbook calls remain untested. The design fixture establishes bounded comparison and synthesis behavior, not general design correctness or implementation performance. The 23 juan-mode playbooks and Architect remain pending.
