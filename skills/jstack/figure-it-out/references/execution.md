# Configured delegation

Keep planning and ordinary execution in the parent unless independent work or review warrants a child. Parent-only planning needs no model preflight. Before dispatch, discover setup-jstack in the current catalog or use an explicit authoring path, then read its configuration and T3 Code integration references. If unavailable, report the affected phase incomplete and provide `npx skills add juancamiloqhz/skills --skill setup-jstack` for manual installation.

Capture a fresh unwrapped live capability catalog using file tools or streaming. Use setup-jstack's canonical `scripts/models.py resolve` command with `--project-root`, `--catalog`, `--role` and `--with-source`. Pass a caller-selected config positionally after `resolve`. Retain the resolved absolute config and pass it explicitly to all later resolutions and children. Validate the whole map; leave settings unchanged on failure.

Declare roles by the work: `feature, refactoring`, `bug-fix`, `perf-issue` or `hardest tasks` for the corresponding implementation, and `judgment and prose` for workflow or trail review. These are existing scalar assignments. A helper such as Architect owns its own role semantics. Task decomposition determines child count. Null selections omit target overrides and inherit provider, model and effort; concrete targets pass through unchanged, including options. Revalidate before a later review round and check effective provider/model child capability. Never invent a fallback model or claim diversity from separate inherited children.

Prefer native same-provider children only when they support the selected model/options, fresh contexts and lifecycle; otherwise use T3 delegation. Save complete briefs with the task, owned paths, source state, selected config, required check, allowed actions and return boundary. Retain task IDs and use fresh tasks for new rounds. A timeout does not cancel a child; inspect terminal records and pending nested work before claiming completion.

Separate write targets before considering parallel writers. Use isolated checkouts or demonstrably independent files, and serialize until tools have shown assigned-path behavior. A prompt path is not a sandbox or T3 workspace binding. Do not create top-level conversations merely to obtain child isolation. The parent integrates artifacts, resolves conflicts and owns shared plan and trail writes. Retain useful briefs and receipts; remove owned temporary capability captures after the run.
