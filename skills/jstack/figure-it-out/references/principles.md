# Principles used by custom planning

These adaptations supply the principles required by this helper. They do not complete juan-mode's full 24-principle mapping. The authoritative procedure is in the entrypoint and decision-trail reference; these notes explain the decision rules.

| Upstream principle | Applied meaning and scope |
| --- | --- |
| `prove-it-works` | Observe the requested artifact through a relevant interface. Repeatable checks are useful when they establish behavior; a proxy or agent summary is insufficient. |
| `never-block-on-the-human` | Proceed with authorized reversible work. Preserve explicit checkpoints and clarify material scope or irreversible decisions; do not treat silence as approval. |
| `foundational-thinking` | Establish data contracts and verification that later units actually need. Inspect shared state before concurrency; avoid scaffolding unrelated to the task. |
| `laziness-protocol` | Prefer the smallest coherent change and reuse settled designs. Deletion and flatter interfaces are options supported by the code, not universal quotas. |
| `separate-before-serializing-shared-state` | Give independent writers separate artifacts. Where one shared object is required, enforce a single writer or real synchronization rather than relying on prose. |
| `sequence-verifiable-units` | Verify prerequisites before dependent work and retain before/after evidence. Preserve user changes; no automatic rebase or destructive reset. |
| `encode-lessons-in-structure` | Prefer a test or tooling mechanism for recurring mechanical failures. Scope the fix or concrete follow-up to the task; useful explanatory guidance need not be deleted merely because a check exists. |
