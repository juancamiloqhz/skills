### Autonomous run

**You own the exit condition. Define done, then drive to it without stopping.** Reading this procedure for authoring or evaluation does not activate juan-mode or start an unattended run.

1. State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N PRs merged, pixel-diff zero). Identify the actual artifact and verification command, existing work to preserve, action boundaries and any explicit runtime or budget limit. If the predicate requires an action outside current authority, name that boundary; do not quietly weaken the predicate.
2. Pick the wake mechanism using the current runtime's supported continuation tools in place of Cursor's `/loop`. While work can proceed in the active turn, keep iterating. For delegated work, use native completion events or T3 task notifications, retain task IDs and inspect terminal results plus pending child runs before acting; do not launch duplicate work. For authorized PR monitoring, the parent links and uses `watch_pull_request`, then yields for its wake rather than polling or spawning a watcher. A wake supplies new evidence, not proof of readiness or permission to merge. Other events and a fallback heartbeat need an actually supported mechanism. Size an authorized fixed interval to when the result is worth re-checking; use a long event-fallback heartbeat only when separately authorized. A persistent T3 schedule requires an explicit recurring-work request, recorded ownership/cadence and teardown; neither this playbook nor "keep going" authorizes one. A provider-native goal likewise requires the user's explicit goal request and its own lifecycle rules. If no authorized wake exists, record the continuation gap and resume point; do not install a hidden timer, promise restart survival or replace a subagent with a new top-level conversation.
3. Each iteration makes the smallest change the evidence justifies, verifies it against the predicate, commits if it advanced, discards changes that didn't help. Belt-and-suspenders that "might help" gets reverted, not left to ride. Use the underlying task's playbook and configured implementation role when delegating, preserving the resolved configuration and model/effort. Inspect verifier evidence, not just an exit code or a child's self-report; tie it to the current artifact. Checkpoint or commit only within current authority, and revert only this iteration's owned changes. Preserve unrelated staged, unstaged and untracked work.
   Sequence the work via the **jstack-principle-sequence-verifiable-units** principle skill, verifying each unit before the next instead of batching checks at the end.
4. Mid-run discoveries are yours. Address broken skills, related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups, and fixable drift yourself via the matching available juan-mode procedure within the agreed objective. Put out-of-band fixes in their own PR when that work and publication are authorized; otherwise preserve the finding and continue independent authorized work. Do not park reversible in-scope work for the human. Surface only irreversible actions, genuine product or preference calls no experiment can settle, missing authority, or a real dead end. Keep the predicate as the main drive, and return to it after each side fix. Do not alter a verifier to hide a failure or broaden permissions to bypass a blocker.
5. Checkpoint every iteration via the **jstack-show-me-your-work** skill, a row for what changed and whether the predicate moved. Keep one coordinator-owned trail with evidence for retained and discarded attempts, the current artifact, pending task/watch/schedule IDs and the next action. Follow that helper's audit and configured review requirements at handoff; if a required review or evidence is unavailable, report it incomplete rather than inventing a passing review. Keep routine logs in task-owned scratch unless the repository retention policy requires a concise durable record.
6. Stop when the predicate is met. A plateau is not a stop, so keep going and pivot your approach to push past it. Surface a genuine dead end rather than spinning, and never relax the predicate to declare victory. Confirm the final artifact and any required child work, then distinguish verified completion from blocked, paused, budget-limited or review-incomplete work. Honor explicit stop requests and hard runtime limits. Record a recoverable checkpoint when completion is unavailable. End only the run's owned watches or authorized recurring work; preserve unrelated schedules and use the host's required PR unwatch-on-handoff behavior.

**Reply:** the exit condition, iterations run, what landed, what was discarded, final predicate state. Include evidence, outstanding continuation or review gaps, and the trail helper's Attention section when a trail was produced. Distinguish local commits from published or merged work.
