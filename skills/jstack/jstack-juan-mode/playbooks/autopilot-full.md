### Autopilot-full

**You own the verdicts, never the PRs. One owner carries each PR from build to merge, and nothing merges until your swarm, which never wrote the code, has proven the code that lands.**

Reading this internal procedure for authoring or evaluation does not activate juan-mode or start a program.

A verdict covers one patch and green CI covers one head. Step 4 runs a full swarm once, and again only for a major change. The patch-id rule in `playbooks/shipping.md` can carry a lane's result, and every new head needs its own green CI.

1. **The operator's gates come first.** The grant covers only the queue's items, so items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go. Record the queue, named holds, publication and merge grant, concurrency limit and any audit-schedule authority before dispatch. A missing dependency or authority blocks its affected action, not independent authorized work.
2. **Spawn one owner per PR, and keep its work where a replacement can find it.** Resolve the forge once for the program. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr` for every PR operation. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`). Each owner is a logical T3 delegate that builds, opens its PR per [Opening a PR](opening-a-pr.md), proves the change on the real artifact, babysits to green per [Babysit](babysit.md), and merges once steps 4 and 5 clear it. Discover and read the actual helper packages. Resolve the implementation role and any hardest-task override through mode preflight; preserve the selected absolute configuration and model/effort. Use `delegate_task` with `isolation: "worktree"` for separate checkouts from the parent local commit, verify the assigned base, and do not assume uncommitted edits were copied. A worktree is not a cloud VM. Keep the logical owner across fresh delegated rounds with its complete brief, findings and artifact pointers; retain each task ID and worktree/branch binding. The root links every PR, owns native watches, ends the turn for wakes and routes findings to the owner. Children return evidence instead of polling or registering watches.

   Open the PR early so CI and bots run alongside the work. Honor explicit draft or local-only limits and the actual publication grant; disclose their effect on this delivery contract. The code is ready only after the slop-strip (the **jstack-deslop** skill) and the `/jstack-no-comments` pass, so the full swarm runs on finished code. Then rebase onto current trunk and report the code-ready head before self-proof, so verification runs on the base the patch lands on. Report every later head, and merge-ready once self-proof, CI, and babysit are done. Fix rounds stay on that base unless trunk conflicts or breaks CI, because each rebase restarts CI. Run the repo's checks for the touched paths on the committed head before the code-ready push and before a later push that needs a verifier.

   Assume the child checkout or agent becomes unavailable. Soon after starting, push and start a decision trail in a root-owned recoverable directory outside disposable child worktrees per the **jstack-show-me-your-work** skill, then push after every unit worth keeping. Record that absolute store path in each brief. Whoever spawns a subagent reports its task ID, state and a stuck-after runtime from past runs of its kind to the root for that store, so the root can probe it if the parent dies. The root serializes shared registry and canonical trail writes; owners return updates and evidence rather than concurrently appending to a shared file. Preserve the latest owned push, base/head, active children, pending questions and verdict identities there. Missing runtime history is an explicit estimate, not an invented past measurement. Keep recoverable records under the repository retention policy. Force-push only your own branch, with `--force-with-lease` pinned to the SHA you last pushed or took over, and on any push you did not make, stop and report to the root. Check the remote against that recorded lease; never adopt an unexpected SHA merely to make a force-push succeed.
3. **Run owners in parallel off trunk, never stacked,** so each PR lands on its own. Serialize overlapping work and respect observed host capacity and the recorded in-flight limit. Dependent work uses merge-then-branch here; a base-chained deliverable belongs to Autopilot-stack.
4. **Swarm-verify once.** A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A rebase, a merge-conflict resolution, or a minor fix gets a single verifier at the new head. Fan out independent verifiers at the code-ready SHA per the **jstack-swarm** skill. They re-run the gates, prove the load-bearing behavior live on the real surface through its control skill (such as **jstack-control-ui** or **jstack-control-cli**) or a named driver, and audit the diff. The verdict is not clean without the live lane, or before you audit the merge-ready report's receipts, because no lane trusts a claim it has not checked. Resolve `swarm workers` through the configured contract for both the full swarm and single verifier; the owner cannot verify its own work. Pass the full brief, exact base/head, scope and evidence location. A single verifier assesses the new head and affected behavior, citing reusable lane evidence under [Shipping](shipping.md) without relabeling old receipts. Keep a current-head assessment and fresh CI even when the patch is unchanged. Missing, errored or untested required proof leaves the verdict incomplete. Use Shipping's evidence rules, not its root-owned landing sequence.

   Send every proven finding, whatever a lane labeled it, to the owner in one fix-forward, with a red test across every site with the same defect. A defect trunk shows without the PR is recorded against trunk and does not gate the PR, but one the PR copies or newly reaches is the PR's own. Never push a fix yourself, because each branch has one writer. Replace a stuck owner instead, under step 6's stop-or-isolate rule.
5. **The owner merges only what you verified, tested on the trunk it lands on.** Green CI alone never authorizes a merge. Once the swarm's lanes have started, merge prep rebases onto current trunk, reports the new head, and waits for green CI. Apply step 4 at the new head; neither a matching patch ID nor old green CI replaces that assessment.

   Right before merging, fetch trunk and ask whether its changes can affect the patch, because rebasing for every trunk move never ends. Rebase and wait for CI when the code that would land was never tested, as with a conflict, a file both sides changed, or a change to which checks run for the PR. A lockfile both sides changed needs no rebase when a frozen install passes on the merge result and the packages the PR changes resolve there as on the head, because that install tests the lockfile that would land, and a failing install means the rebase must repair it. When trunk changed a caller of the patch or something the patch depends on, such as code it calls or a dependency version, run the patch's checks on the merge result and merge on a pass. Otherwise merge. If trunk would force a third rebase past merge prep, hold and report to the root, which sequences the colliding work. Record the merge-prep rebase separately and count additional required rebases since it; hold before the third additional rewrite. Inspect the actual merge result in isolated, task-owned state when it needs checks. Missing merge-result or dependency-resolution evidence leaves the relevant exception unproven. Record the grant and current root verdict before owner merge work; named holds and repository merge policy still apply. Use an expected-head guard where supported, read back the actual merged state and confirm the forge's merge commit on fetched trunk. A queued or unknown result stays unresolved; reconcile it before retrying or advancing.
6. **Run the root layer.** Anything that loosens a gate, such as a raised budget or an allowlist entry, needs a verifier's proof and then your fresh countersign, because the owner is the one who wants green. Under a grant that covers approvals, that countersign is the approval, and the owner's record of it points at your countersign for a lane to check. A disabled or soft-failed check always comes out, because it stops guarding every case. Never give or bypass an approval the forge enforces, because no countersign covers it.

   Audit hourly until no delegated work is left, because long runs drift and agents stall silently. A persistent T3 schedule needs an explicit recurring-work request, not just a general go. When authorized, bind it to this coordinator and record its ID, cadence, next run and teardown authority; reuse an existing owned schedule. Otherwise disclose missing hourly coverage, audit at active-turn and supported event boundaries, and leave a recoverable checkpoint. Native goals also need an explicit request; do not substitute shell polling or hidden timers. Each tick re-reads this playbook from its canonical jstack source, not the consuming project's unrelated trunk; record source identity and disclose unavailable freshness checks. It fixes drift, such as an unreported head or an unrecorded agent, by having its owner record it, because drift is a gap in the record, not a stall. It probes every agent, down to the leaf lanes, and judges each by its side effects, because status text and summaries can hide a stuck child. An agent is stuck when it errors, cannot start turns, or shows nothing new past its stuck-after runtime, and so is an owner that has neither pushed nor written a trail row by the first tick. One waiting on you or the operator is not stuck, so answer it. Request cancellation of a stuck agent promptly and inspect terminal state plus pending children. Replace needed work without waiting for a polite report, but confirm the old writer stopped before reusing its writable scope, or isolate the replacement on a distinct checkout/branch and reject late writes. Unknown state is not a stopped writer. A missing record alone calls for reconciliation, not replacement; answer a pending question only when the existing brief and authority determine the answer, otherwise surface it to the operator. A tick that changed something for the operator ends by catching them up per the **jstack-ketchup** skill, and one that changed nothing stays quiet. Discover and read the full `jstack-ketchup` and `jstack-bro` files through the catalog or explicit installed paths; the reporting call does not resume work or grant action authority. If the host cannot load them, report the dependency gap rather than claim the helper ran. Drain or checkpoint remaining children; a completed turn with pending child runs is not a completed program.
7. **Stand down at once on the operator's stop.** A hold reaches every owner as a zero-writes order. Each reports where it stands and keeps its brief until the operator releases it. Follow [Pause safely](pause-safely.md): cancel owned tasks, confirm terminal state with no pending children, reconcile in-flight writes and unwatch owned PRs. Change only this program's audit schedule under the stop's scope or recorded teardown authority. Preserve briefs and unresolved writers; a zero-writes message is not proof that writing stopped.

**Reply:** catch the operator up per the **jstack-ketchup** skill, covering each PR's state and verdict, what merged, countersigns and why, and open operator gates, with links to each PR and the trails. Keep exact head, task, watch and schedule identities in the root record; surface unverified lanes, cadence/restart gaps and the next authorized action when they affect the operator. Reconcile PR links and unwatch on handoff.
