### Autopilot-stack

**You own the stack, never the landing. Build and verify the queue with full autonomy, then hand the operator one linear base-branch stack to review and land.** The sibling of [Autopilot-full](autopilot-full.md). Reading this internal procedure for authoring or evaluation does not activate juan-mode or start a program.

1. **Run the owner loop unchanged.** Resolve the forge once for the program. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr ...` for PR create, edit, view, watch, and merge operations. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`). One logical owner per PR owns its change end to end: build, first push, a ready PR opened before self-proof, self-proof (gates, CI, receipts), skeptical Bugbot triage per `../references/bugbot-triage.md`, a slop-strip (the **jstack-deslop** skill), `/jstack-no-comments` (the **jstack-no-comments** skill), and babysit to green per `playbooks/babysit.md`. Owners parallelize when the work is self-contained. Within about 15 minutes, every owner starts a `decisions.tsv` trail per the **jstack-show-me-your-work** skill, pushes its first branch snapshot, and opens the PR ready by default. Honor explicit draft or local-only limits and report their effect on this delivery contract; publication requires actual authority. After that, the owner pushes its branch again after every verifiable unit (hooks on, a WIP commit is fine). Keep the trail uncommitted and return it in the report. Owners also keep the `children.tsv` of Autopilot-full step 2. Read that step for configured implementation roles, fresh delegated rounds, T3-bound worktree isolation, task/base identity and helper discovery. Preserve the selected configuration and model/effort, current user limits and observed concurrency capacity. Apply those owner mechanics without importing merge authority. The root links every PR, owns `watch_pull_request`, yields for host wakes and routes findings back to owners. Children return evidence instead of polling or watching. Read [Opening a PR](opening-a-pr.md) and [Babysit](babysit.md) for their actual publication and status contracts; unavailable proof or required reviews remain incomplete.
2. **Audit on a real loop.** The root runs an audit tick every hour. Use the explicit recurring-work authorization and scoped T3 schedule contract in Autopilot-full step 6. A generic go or full-autonomy grant alone does not authorize a persistent schedule or native goal. If no authorized hourly wake exists, disclose the cadence gap, audit at active-turn and supported event boundaries, and retain a checkpoint; do not claim unattended coverage or install a hidden timer. At each tick, refresh this procedure from its canonical jstack source, for example `git show origin/main:skills/jstack/jstack-juan-mode/playbooks/autopilot-stack.md` in the jstack source checkout. In a consuming project, resolve the canonical package source rather than reading that project's unrelated trunk. Retain source identity and report unavailable freshness checks. Audit the operation against the inspected procedure. Fix drift during that tick. Probe each owner with a generic liveness or status check. Count only side effects as progress: commits, pushes, PR or check deltas, and store reports. Treat a lane that passes its expected runtime without a side effect as stuck. Request cancellation promptly. Confirm terminal state with no pending children before reusing writable scope, or isolate the replacement on a different checkout/branch and reject late writes; a cancellation request alone proves nothing. Replace needed work without waiting for a polite report. Probe all subagents and end the tick per Autopilot-full step 6.
3. **Hold the operator gates.** State-then-wait, so a request to state the plan is not a go. On the operator's stop, every owner takes an immediate zero-writes hold. Follow [Pause safely](pause-safely.md) to confirm owned child shutdown, reconcile in-flight writes, preserve briefs and unwatch owned PRs. Change an audit schedule only when the stop covers it. No new dispatch, topology mutation or landing follows a hold.
4. **Verify each round.** The owner reports its code-ready head SHA once the shipped code is final, and STACK-READY with the exact head SHA when its loop is green. The root verifies each round per Autopilot-full step 4, with STACK-READY in place of merge-ready. Nothing enters the stack unverified. Retain the exact verdict base/head, stable patch identity, independent lane receipts and gaps; CI green or STACK-READY alone is insufficient. Keep all required live, gate, audit and regression lanes from Autopilot-full. Resolve verification through the configured **jstack-swarm** contract; owners cannot verify their own changes.
5. **Append on a clean verdict, never ship.** No owner merges, arms auto-merge, or closes. The root also performs none of those landing actions in this route, even under a broader full-autonomy grant. A clean verdict appends the PR to the one linear base-branch stack, in verified order or an order the operator specified.
6. **Single writer on topology, parallel writers on builds.** Owners push only their own branches and report the tip, current base, and intended parent. The root is the only topology writer. Record each PR's branch, actual base, old parent tip and head before rewriting any link. Quiesce the affected owner writer before the root rewrites its branch, preserve unrelated work, and resume with the new base/head only after the topology update is confirmed. An unconfirmed writer or changed remote lease blocks that mutation. To append a PR, fetch the intended parent, rebase the child branch onto that exact parent tip, push only the owned branch with an expected-ref `--force-with-lease` after an `ls-remote` check, and set the PR base to the parent branch. Create it with `origin pr create --status open --base <parent-branch>` or `gh pr create --base <parent-branch>` according to the resolved forge. Retarget an existing PR with `origin pr edit <pr> --base <parent-branch>` or `gh pr edit <pr> --base <parent-branch>`. Only the root PR targets trunk. Preserve only the child's own commits when its parent was rewritten, using the recorded old parent and new parent tips for the rebase. Prefer an available structured PR tool for retargeting per Opening a PR, then read back actual base/head state. Never submit or register the chain through `gt`.
7. **Absorb drift at the root, then re-verify what moved.** The root fetches current trunk and rebases the chain from bottom to top. When a rebase surfaces conflicts in an owner's files, that owner fixes its own slice and the root pushes the result. A rebase rewrites every SHA above it and voids verdicts at the old SHAs. Apply the patch-id rule in [Shipping](shipping.md) at each verdict SHA, using the recorded original base-to-head diff and the current actual parent-to-head diff. Do not import Shipping's merge sequence. Missing patch evidence stays unverified. Anything that is no longer valid goes back through this playbook's step 4 before delivery. Re-run mergeability and CI after every rewritten push even when the patch-id is unchanged. A changed implementation needs a fresh independent verdict. Do not label the complete chain verified while a required ancestor, lane or current-head check is blocked; report its exact gap and continue independent authorized work. The countersign rule is unchanged from Autopilot-full. A genuinely new pin raises a stop for the root's fresh countersign. Absorbing drift of landed values is not a raise.
8. **Deliver the chain.** The deliverable is one linear chain of verified PRs, reviewable bottom-up in the resolved forge, every link carrying its verifier verdict in the PR body or a comment. The operator reviews and lands it, with their own clicks or by arming merge-when-ready. Publish verdicts only within existing PR-body/comment authority; if publication is unavailable, preserve proposed evidence locally and state that the published delivery remains incomplete. Confirm every link is still open with its intended base/head and current evidence, record anything excluded, and unwatch the run's PRs before handing back. Stop an owned audit schedule only under its recorded teardown authority. Live wake continuation and restart durability require separate evidence.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

**Reply:** links to the stack root and tip, a one-line verdict summary per link, and anything parked or excluded with the reason. Include the exact branch/base/head chain, verified versus pending lanes, decision-trail location and any unresolved task, watch or audit state. Distinguish local fixture results from actual forge delivery.
