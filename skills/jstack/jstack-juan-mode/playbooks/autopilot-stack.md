### Autopilot-stack

**You own the stack, never the landing. Hand the operator one linear stack of base-chained PRs to review and land.** [Autopilot-full](autopilot-full.md) holds except for how verified work leaves. Each tick re-reads both playbooks from the canonical jstack source, and this one wins where they differ. Use Full's canonical-source, T3 configuration, root records, audit authority and stop-or-isolate contracts. Reading for authoring does not start a program.

1. **Run Autopilot-full's owners, minus the landing.** Owners report STACK-READY in place of merge-ready. They never rebase onto another branch, trunk included, and never retarget, merge, close a PR, or arm auto-merge, because the root owns the chain's topology and the operator owns the landing. When an item depends on another, its owner branches from that item's branch, not from trunk. The root arranges the exact parent base in the assigned T3 worktree before handing it to the owner; uncommitted parent edits are not inherited. Neither root nor owners merge, close or arm auto-merge under this route, even with a broader full-autonomy grant.
2. **Give the topology one writer.** Owners push only their own branches and report each tip and its intended parent. Only you rebase or retarget a link, because two writers on one chain undo each other. Append each clean PR in dependency order, with its base set to its parent's branch (`origin pr edit <pr> --base <parent-branch>` or `gh pr edit <pr> --base <parent-branch>`). Never require `gt`. An owner takes your push as its new base and lease, and on a conflict resolves its own slice for you to push. Record old parent tips, actual bases and heads before any rewrite. Quiesce affected writers before topology changes, preserve unrelated work, replay only each child's own commits onto the exact new parent, and publish with an explicit expected-ref lease. Unexpected remote movement blocks that mutation. Prefer an available built-in PR tool for retargeting per [Opening a PR](opening-a-pr.md), then read back actual remote head/base. Resume an owner only with its confirmed new base and owned lease.
3. **Absorb drift at the root.** Until landing starts, apply Autopilot-full step 5's test to each link and rebase the chain bottom-up where it calls for one. Then apply the patch-id rule link by link, since a link's base is its parent. Compare the recorded immutable verdict diff with the current actual parent-to-head diff. Apply Full step 4's full-versus-single verifier rule at each new head and rerun current-head CI. Missing proof or a blocked ancestor prevents claiming the complete chain is verified. Keep the root's countersign and writer-ownership boundaries while correcting drift.
4. **Deliver the chain, then keep your hands off it.** Each link carries its verdict in its PR. Once landing starts, nobody writes to the chain except the post-merge retarget that `playbooks/shipping.md` sanctions, because a second writer breaks a landing in flight. A mid-landing problem goes through you to the operator, and any fix waits for the operator's go. That go ends the current landing pass before a repair or wider rewrite; reassess affected heads and obtain new verdicts before starting another pass. The Shipping coordinator alone performs its sanctioned immediate-child move. Publish verdicts only within existing PR-body/comment authority; otherwise keep proposed evidence locally and disclose incomplete published delivery. Confirm each delivered link's actual base/head and current evidence. The operator's separate request may start Shipping; STACK-READY alone does not.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

**Reply:** catch the operator up per the **jstack-ketchup** skill, with links to the stack root and tip, a one-line verdict per link, and anything parked or excluded with the reason. Read the full discovered helper as in Full; report missing proof and pending resources honestly, reconcile links and unwatch on handoff. Stop only this program's audit under its recorded teardown authority.
