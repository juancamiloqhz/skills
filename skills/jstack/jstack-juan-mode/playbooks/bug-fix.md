### Bug fix

**You own this task. Plan, review, verify.** Delegate investigation and the fix to subagents, stay in the lead.

Be scientific. Every shipped line traces to runtime evidence. Belt-and-suspenders that "might help" is a hypothesis, not a fix. It does not ship. When evidence refutes a hypothesis, revert what it motivated. The smallest change the evidence justifies ships, nothing more.

1. Reproduce it yourself on the matching surface via the control skill (Non-negotiables), even when a debug or instrumentation protocol says to ask the user to reproduce. Ask the user only with a stated, specific reason the control surface cannot reach the target, and only after driving it as far as it goes. If it won't reproduce directly, synthesize the trigger, tighten conditions, or instrument until it fires. Discover and read the matching control helper, including `jstack-control-cli` for terminal apps. Retain commands, outputs and the reached boundary; missing access or tools leaves reproduction incomplete and does not authorize installation.
2. Binary-search the cause. Form the candidate hypotheses, then rule them out until one survives. Seed them with `jstack-how` over the affected subsystem and the **jstack-why** skill for regression history. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, eliminate. When program state is unclear, add instrumentation or logging and read it as the code runs. Don't guess. Drive a long or stubborn hunt with bounded continuation in the current task, preserving its scope and stop conditions; this does not create a recurring schedule. Confirm the surviving *mechanism* with runtime evidence before the step-3 architect/interrogate fan-out. Use the helpers' configured roles, preserve evidence gaps, and remove owned temporary instrumentation after capturing its observations.
3. Plan the fix. If it crosses a function boundary, `jstack-architect` first, returning a design before this step's implementation delegation. Delegate implementation to a subagent using the configured `bug-fix` role, or `hardest tasks` when warranted by the mode's difficulty rule, with a specific scope. Resolve through the mode's preflight and retain the selected absolute configuration; no fixed-model fallback. For a cheap local test path, follow `jstack-tdd` during implementation and retain the failing run before production edits; step 5 records that order in history.
4. Verify on the same surface. The original repro now passes. "Inconclusive" or wrong-surface is not a pass. Flag it. Unit tests show branch behavior, not bug absence. Inspect the delegated diff and repeat the original public reproducer yourself; retain actual failing and passing output, not just the child's summary.
5. Stage the commits so the failing repro lands before the fix in git history. See the **jstack-tdd** skill for the failing-test-first cadence when the bug has a cheap local test path. Skip it when the test would be expensive, integration-heavy, or unclear.
   This is the canonical **jstack-principle-sequence-verifiable-units** principle skill, the failing test first and the fix on top. Create commits only within the requested authority; otherwise retain the before/after artifacts and proposed order. A deliberately failing test commit is evidence, not an independently merge-ready change. Preserve unrelated work.
6. Run **Opening a PR** when publication is authorized. That procedure remains unavailable in this package; disclose the gap rather than claiming it ran. Preserve local-only delivery and existing publication authority. This playbook does not authorize merging or installation.

**Reply:** what was broken, root cause, fix, how you verified. Paste failing-then-passing repro output verbatim.
