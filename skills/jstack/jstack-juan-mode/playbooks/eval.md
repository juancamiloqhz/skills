### Eval

**You own the experiment design. Plan, blind, run, synthesize.**

**Non-negotiables for blinding:**

- No `eval`, `test`, `judge`, `experiment`, `rubric`, `score`, `compare`, `benchmark`, `candidate`, or `arena` in any directory, file, or prompt the candidate sees.
- The candidate prompt looks like an organic user request. State the goal, not the meta.
- No chain-eliciting cues. Don't ask the candidate to list which skills, principles, or files they applied. Ask for design notes generally and grade chain-following from code shape, not self-report.
- Sanitize directory and slug names. Use project-shaped names a user might pick.
- Don't tell the candidate other candidates exist.
- The judge can know it's judging but sees outputs by sanitized label only, never by model name.
- Comparing two variants: one judge scores both sets in a single pass on one scale, blind to which set each came from.

**Steps:**

1. **Frame.** State what variant is under test and what behavior counts as success. Write the rubric (3-6 concrete criteria) for the judge only. Hold it back from candidates. Discover **jstack-arena** and read its full procedure and execution reference. Resolve the selected absolute configuration and fresh catalog before spending candidate work. Preserve its configured panel and judge pool. Require at least two distinct effective candidate models and an eligible judge from a different family than the coordinator, as in Arena Phase C. Repeated inherited seats are not different models; an unknown identity does not prove diversity. If these requirements fail, stop incomplete without substituting models or changing settings.
2. **Set up sanitized environments.** Per-candidate working dir with the variant in place. Plant any context an organic task would have: a project skeleton, the skills the candidate would naturally read. Inspect task-facing paths, files and metadata for leakage before dispatch. Keep the rubric, variant/model mapping and orchestration records outside candidate scope. Use T3 Code worktree isolation when a separate checkout is needed; inspect its assigned path and contents before accepting it as blinded. Uncommitted parent edits are not copied. Owned scratch directories suffice for independent artifacts that need no checkout. If the transport exposes comparison context that cannot be removed, report contamination rather than claiming a blinded run.
3. **Author one organic prompt.** What a user would type. No leakage of what's being measured.
4. **Spawn N parallel candidates** on different models per the **jstack-arena** skill's Phase B. Each works in its own sanitized dir. Same prompt to each. Use fresh contexts without parent-history inheritance and preserve the common organic task; vary only necessary owned-path bindings. These are specialized blinded briefs, not generic mode wrappers. The coordinator retains the selected configuration and performs preflight for dispatch; do not expose its full role map, the experiment procedure or comparison labels to candidates. If the behavior under study needs nested configured delegation, establish a non-leaking execution contract before running it, or report that case incomplete. Respect capacity and path ownership, wait for all candidate work to become terminal and freeze outputs before judging. Missing output is a dropout, not an invented observation; fewer than two usable outputs cannot establish this comparison.
5. **Spawn one blinded judge** on a different model family per the **jstack-arena** skill's Phase C. Judge sees outputs by sanitized label and the rubric, never a model name. Revalidate the selected configuration and current catalog. Use one fresh read-only judge for both sets in the same pass. Exclude identity-bearing filenames, headers and dispatch records from its inputs; preserve substantive output and record any redaction privately. Do not relabel same-family judging as satisfying this requirement.
6. **Verify the chain from transcripts, not self-report.** Read run-specific tool/read evidence exposed for the owned candidate tasks. Retain their task and run identities. For T3 Code-owned children, use scoped task status and child activity reads, consuming pagination and truncated items when needed. Summarized activity alone does not prove every file read. Do not glob private provider transcript stores or read unrelated conversations. Look at which files each candidate actually opened. Grade chain-following from the files it really read plus the shape of the code, never from the candidate's own claims. If actual read evidence is unavailable, mark chain-following unverified; distinguish supported artifact findings from that gap instead of treating self-report as a pass.
7. **Read every candidate output yourself** end to end. Compare to the judge's verdict. Disagreement means a model is biased or the rubric is ambiguous. Synthesize. Preserve original outputs and report contamination, dropouts, diversity failures and evidence gaps with their effect on the recommendation. A recommendation does not authorize promotion, implementation, publication or installation.

**Reply:** variant under test, rubric, per-candidate notes, judge's verdict, your synthesis, and a recommendation for whether to promote the variant.
