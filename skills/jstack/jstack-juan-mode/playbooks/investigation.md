### Investigation

**You own the answer. Plan, route, write.**

Investigation requests are read-only. They produce a cited explanation or a recommendation, not a code change. Preserve source, configuration and external records; only assigned temporary findings may be written. Use the mode's discovered helper paths and selected absolute model configuration. A missing helper or failed delegated phase leaves the affected investigation incomplete.

1. Route through the **jstack-how** skill. For motivation questions, also route through the **jstack-why** skill.
2. Throughput checkpoint stays one line: `throughput checkpoint: n/a, read-only investigation`.
3. Produce the `jstack-how`-shaped output (Overview / Key Concepts / How It Works / Where Things Live / Gotchas), or a recommendation with a tradeoffs table if the request is a decision between alternatives. Preserve Why's separation of facts, inference, unknowns and source coverage in either format; do not turn a plausible rationale into a confirmed reason.
4. Apply the **unslop** skill to the reply. Discover the intended pstack dependency through the current catalog or an explicit authoring path and read it in full. Respect host invocation restrictions; missing, ambiguous or blocked Unslop leaves the writing check incomplete without installing or substituting a package.

No PR, no babysit, no `jstack-architect` unless the investigation precedes a code change. If it does, hand back to the user and re-route to Bug fix or Feature. Carry forward already-granted implementation authority, but do not claim a pending route ran or start implementation inside this investigation.

**Reply:** the investigation output. For "are we sure?" answers, include your real judgment with reasons. Push back if the premise is wrong (see Autonomy).
