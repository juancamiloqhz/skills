### Pause safely

**You own a clean stop. Leave a checkpoint a cold-start agent can resume from.** This is explicit only. On "keep going", "going to bed, keep going", or "don't stop", do not pause. A compaction handoff alone writes a checkpoint and continues authorized work; it does not authorize cancellation or a pause. Reading this procedure for authoring or review does not execute it.

1. Stop at a safe boundary. Finish the current atomic step or back out of it. Start nothing new, and cancel any nested subagents owned by this task. Use retained task IDs with T3 `task_cancel`, then `task_status` to confirm a terminal state with no pending child runs; a cancellation request alone is not proof that writers stopped. Use the native stop/status lifecycle for native children. Preserve their files and unresolved results. If a child cannot be stopped or its state is unknown, record the blocker and do not claim a quiescent checkout. Unwatch this task's linked PRs on handoff. Leave unrelated tasks and watches alone; change a recurring schedule only when the user's pause explicitly covers it.
2. Take no irreversible action to pause. No PR and no push unless you already had one out. An existing PR or pushed branch does not create new publication authority; preserve the user's current limits. Do not merge, install, delete worktrees or change model configuration as part of pausing.
3. Make the work durable. Commit uncommitted edits owned by this task as one clear `wip:` commit on the current branch so nothing is lost. Inspect branch, status, index and diff first; preserve unrelated staged and unstaged edits without including them in the checkpoint commit. If ownership cannot be separated, the branch cannot be committed safely, or commits are prohibited, retain the working files and record the exact gap and recovery paths instead of staging everything or claiming a commit succeeded. If the tree is broken, say so in the commit body in one line. Report remaining dirty work honestly. Do not reset or stash away someone else's edits to obtain a clean tree.
4. Write the resume note off-context. Capture intent, what you were doing, progress and what's verified, current state, next steps, key files, and gotchas. Include the absolute checkout, branch and HEAD, owned versus unrelated edits, child stop evidence or unresolved writers, PR/watch/schedule state, current user authority, mode activation state and any selected configuration path. For the compaction trigger write it to a file like `/tmp/<slug>-resume.md`; use a task-owned location that survives the intended interruption when a restart may clear temporary files. If a show-me-your-work trail exists, point at it instead of duplicating it. Verify the note exists and references recoverable artifacts. Missing storage or incomplete child shutdown remains a stated pause gap.

**Reply:** where you are in the loop, what's on disk versus still in your head (paths, no diff dumps), the commits you made and whether the tree is clean, and the first action on resume. This is a pause, not a final report.
