### Refactoring

**You own the contract. The structure changes. The behavior does not.** Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to the **jstack-figure-it-out** skill. This playbook is the focused-to-medium change.

1. Pin the behavior contract first. Run the **jstack-how** skill over the affected subsystem to learn the contract, then write a characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. If the area has no coverage, write the pin before touching structure. Type check and lint are not a pin. Discover the helper and pass its configured roles, source scope and selected absolute configuration through the mode's preflight.
2. Name the structure the code is missing per **jstack-principle-model-the-domain**. Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today (**jstack-principle-foundational-thinking**, **jstack-principle-redesign-from-first-principles**). If the target crosses a function boundary, run the **jstack-architect** skill for parallel design exploration of the shape before the move, returning a design before step 5. Preserve its configured panel and two structurally distinct candidate requirement; an undersized panel or unavailable helper leaves this step incomplete, without adding seats.
4. Subtract before you add. Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape (**jstack-principle-subtract-before-you-add**). The smallest change that reaches the target shape ships (**jstack-principle-laziness-protocol**). A speculative cleanup that "might help" gets reverted.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave (**jstack-principle-migrate-callers-then-delete-legacy-apis**). No compatibility shims, no parallel old-and-new paths. Spot-check every rename against the actual files. Renames silently miss usages in strings, prose, and back-references. Delegate the mechanical edits to a subagent using the configured `feature, refactoring` role, or `hardest tasks` when warranted by the mode's difficulty rule, with a specific scope (file paths, the names being moved, the behavior to hold). Resolve through the mode's preflight and retain the selected absolute configuration; no fixed-model fallback.
6. Prove behavior is unchanged on the real artifact, not "it compiles" (**jstack-principle-prove-it-works**). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface via the relevant control skill. Discover the matching helper, including `jstack-control-cli` for terminal apps. Inspect the delegated diff and run the public equivalence checks yourself; retain actual output and unmet prerequisites. Missing access or wrong-surface proof is incomplete.
7. Confirm the change is worth keeping. The success measure is reduced reader load (**jstack-principle-minimize-reader-load**). If the diff does not lower reader load somewhere, revert it.
8. Rebase into small ordered commits. A subtraction commit, then the reshape, then any follow-on cleanup. Shape them with the **jstack-principle-sequence-verifiable-units** principle skill, so each behavior-preserving slice stays green before the next. Commit and rebase only within the task's authority and preserve unrelated work; for uncommitted local delivery, retain verified artifacts and the proposed order. Run **Opening a PR** when publication is authorized. Read and follow [Opening a PR](opening-a-pr.md). This playbook does not authorize merging or installation.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.
