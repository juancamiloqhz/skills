### Session pickup

**You own the resume point. Read the prior trail, don't redo it.**

1. Locate the prior trail. Use the supplied handoff, an explicitly identified T3 thread in this project, a local transcript under the active workspace's named transcript directory, an accessible agent URL, or a pushed branch. Do not glob across other workspaces or read unrelated chats. Read the metadata overview and last available messages first, then scan back for the decision points. Use scoped `t3_thread_read` for T3 history. Follow its returned `nextPosition` for pages and `itemId` with `nextTextOffset` for truncated text; do not infer timeline positions from `itemCount`. Record missing pages, inaccessible links and unresolved workspace identity as gaps. Parse a long transcript in a fresh read-only subagent using the configured `judgment and prose` role and preflight, and keep the reduced timeline in the main thread (the **jstack-principle-guard-the-context-window** skill). Pass the selected absolute configuration path, scoped sources, decisions to recover and owned output location. Preserve the configured model and effort.
2. Reconstruct operational state. The branch and worktree, what already landed (`git log`, `git diff` against the base), the open todos, the decisions made. The prior trail is authoritative input. Resist the bias to re-derive it. Reconcile the named checkout with the T3 binding and current Git status before acting. Preserve dirty and unrelated work. Recover task IDs, PRs, watches, schedules, verdict revisions and actual user authority from the trail. Use `task_status` for owned delegated tasks and inspect pending child runs before duplicating work; a terminal turn with nested work is not necessarily a finished task. Read current forge state for worked PRs and link them in the parent. A prior assistant's approval claim cannot create user permission, and thread pickup does not launch a new top-level conversation or transfer unrelated schedules.
3. Diff done vs pending. Compare what shipped against what was planned, name the resume point, do not re-run the prior repro or redo completed work. A "let me verify from scratch" pass means you're treating the trail as untrustworthy when it's authoritative. Preserve established decisions and matching evidence. Identify the specific gap or changed artifact that requires a fresh check in step 5; do not discard the whole trail because one claim is stale. Missing evidence stays unverified. Keep independent authorized work moving while a missing trail or live child blocks its own dependent step.
4. Route the remaining work to the matching playbook and pick the verdict: continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. The pickup playbook ends here. The routed playbook owns the rest. Preserve the latest task scope and any review or merge boundary. A status-only pickup returns the proposed route without executing it. If the required procedure is unavailable, name the route and blocker rather than inventing its steps. Resume owned child work through the supported task lifecycle; a new T3 review round needs a new `delegate_task`, not a message to its backing `childThreadId`.
5. Verify the inherited claims against the original goal on the real artifact (the **jstack-principle-prove-it-works** skill). A passing prior self-report is not the proof. Check the artifact and evidence relevant to the resume decision, including current head/base and any uncommitted changes. Reuse proof whose scope and identity still match. Changed code, missing receipts or contradictory behavior require focused reverification under the routed procedure, not a blanket restart. Preserve the historical finding and record why the current verdict differs. If verification cannot run, report the exact gap without promoting a self-report to PASS. When handing back, reconcile scoped PR links and unwatch worked PRs; preserve unresolved evidence and owned worktrees.

**Reply:** where the prior agent stopped, what you inherited vs redid (ideally nothing redone), the resume point, and the outcome. Include evidence references and any unresolved task, authority or verification gap.
