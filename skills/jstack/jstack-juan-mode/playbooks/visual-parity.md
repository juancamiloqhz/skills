### Visual parity

**You own pixel-exact equivalence. The baseline is the spec. You do not touch it.** Equivalence is verified by image diff, not by eye.

1. Establish the baseline first, before any migration: a visual regression harness that screenshots the current component across its states, plus the target when matching two implementations. No baseline, no parity claim. A blocking prerequisite, not a follow-up. Discover **jstack-control-ui** and read its full procedure. Fix the capture environment, viewport, scale, fonts, data and animation state; repeat unchanged captures to establish stability. Retain the state list, baseline images and comparison command before editing. Missing capture/comparison capability or unstable captures leave this gate incomplete; do not install tools or relax the threshold to bypass it.
2. Anti-shortcut clauses, stated and held: no harness modifications, no baseline tampering, no component restructuring to make a diff pass. If the baseline looks wrong, stop and ask, don't edit it.
3. Migrate one component at a time. Parallelize across worktrees, one owner per component (the **jstack-principle-separate-before-serializing-shared-state** principle skill). Shared primitives migrate first as a blocking phase. Use the selected configuration and fresh catalog for configured component owners, normally `feature, refactoring`; preserve seats and options. Children needing separate checkouts use T3 Code worktree isolation from the parent's committed state, not a path-only branch claim. Serialize shared-primitive changes and recheck all affected components and states after them. Preserve unrelated work and the frozen harness.
4. Verify each component against its baseline via image diff on the matching surface via the control skill. A nonzero diff is a fail. Investigate the pixel delta. Repeat capture, comparison and correction per component until the diff is zero, within the authorized scope and actual execution budget. Use decoded pixel differences, not file-byte equality or visual judgment. A missing state, dimension mismatch, capture error or exhausted run remains failed or incomplete; report the remaining delta and resume point. Keep each result tied to its component, state and current artifact. Do not create a recurring schedule as a replacement for Cursor's loop command.
5. Run **Opening a PR** per component or per safe batch. Read and follow [Opening a PR](opening-a-pr.md) within the user's publication boundary. A parity pass does not authorize merging or installation.

**Reply:** components migrated, the diff result for each, the baseline harness location, what's left.
