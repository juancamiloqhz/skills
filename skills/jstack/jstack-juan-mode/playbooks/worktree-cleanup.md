### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work. Reading this procedure for authoring or audit does not authorize cleanup.

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh` (the **jstack-principle-build-the-lever** skill), following its [inputs and exit contract](../references/worktree-audit.md). It reads complete paths from `git worktree list --porcelain -z`, including detached checkouts, never hand-typed (the **jstack-principle-encode-lessons-in-structure** skill). Select the actual base ref and refresh it separately when authorized; the audit does not fetch implicitly. It classifies each worktree by size, age, merge state, tracked/untracked/ignored work, supplied PR state and scoped chat/task usage, then suggests a bucket. Collect T3 binding and project-scoped history evidence separately; missing or incomplete evidence stays unknown. Background slow scoped transcript inspection and retain its task IDs.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (the **jstack-principle-prove-it-works** skill). Get that set from the user or supported T3 project/sidebar metadata and cross-check every candidate. The pinned set wins even when a script suggests a candidate. Reconcile Git's full inventory with T3 workspace bindings and owned child tasks; `t3_worktree_list` omits detached worktrees. A completed or settled chat alone does not establish that its checkout is unused. Hold unresolved usage; do not infer permission from age, size or an empty transcript search.
3. Verify usage before deleting. For every recent-chat or `verify-usage` row, or anything you doubt, fan read-only subagents out to the explicitly scoped transcripts and report whether the chat is pinned or ongoing and which worktrees its children touch (the **jstack-principle-guard-the-context-window** skill). Use the configured `judgment and prose` role and preflight, preserve its model/effort, and pass the selected absolute configuration path, evidence scope and owned report location. A pinned chat can spawn arena and repro trees into sibling worktrees via background subagents, even when their names never hit the sidebar. Inspect retained task IDs through their owning lifecycle, drain these inspection children and retain unresolved findings before deciding.
4. Pause on irreversible loss. Tracked uncommitted edits, untracked files and ignored artifacts are held until their ownership and recovery are established. Show relevant diffs or name the files and get a decision for potential loss; untracked does not mean throwaway. Within the user's cleanup scope, clean, actually merged and confirmed-unused worktrees can proceed. Closed PRs, stale PR verdicts and squash merges without current source/patch proof do not establish that HEAD landed. Preserve current/main, locked, active, unknown and unmerged worktrees; abandonment requires a separate explicit loss decision. An audit-only request stops at the report.
5. Prune the confirmed set. Immediately recheck the exact registered path, HEAD, status including ignored files, branch/ref preservation and current task/thread ownership against the assessed evidence. If any changed, hold and reassess. Use `git worktree remove -- <path>` first. Use `--force` only for specifically approved remaining files after the loss decision in step 4; never force an active or locked checkout. If a directory survives, inspect it again. Recursive removal requires explicit scope for that exact path and its contents, verified ownership and no active users; do not delete a reused path, symlink target or unrelated artifacts. Preview stale metadata with `git worktree prune --dry-run`; prune only when all affected registrations are confirmed disposable. Branch refs normally survive removal, but verify reachability for detached HEADs before deletion. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. On macOS with `xcrun` available and explicit cleanup scope, inspect XCTestDevices clones, unavailable devices and installed runtimes before selecting targets. The upstream operations are `xcrun simctl --set testing delete all`, `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes; bulk deletion requires approval covering the full set and confirmation nothing is in use. On Linux or without the tools, report this step inapplicable. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, provider backups and snapshots under explicitly identified paths, and package caches such as pnpm, uv, brew or yarn. Clear only inspected targets within the user's requested scope, preserving caches they asked to keep. A worktree cleanup request alone does not authorize deleting unrelated provider state or all caches.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work). For an audit-only run, report proposed removals and reclaimable sizes without claiming space was reclaimed. Report incomplete checks and distinguish filesystem free-space change from estimated worktree size.
