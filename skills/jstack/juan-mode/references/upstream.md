# Upstream and intentional differences

Adapted from [poteto-mode](https://github.com/cursor/plugins/blob/11713c683fe4add4fd403ea880580abbc9e0875f/pstack/skills/poteto-mode/SKILL.md) and its [playbook directory](https://github.com/cursor/plugins/tree/11713c683fe4add4fd403ea880580abbc9e0875f/pstack/skills/poteto-mode/playbooks) at revision `11713c683fe4add4fd403ea880580abbc9e0875f`, inspected on 2026-10-11. The bundled [MIT license](../LICENSE) retains Lauren Tan's attribution.

This foundation implements the entrypoint, complete route registry, dependency discovery, model preflight and execution instructions. The bundled how/why procedures begin the shared-helper group. The 23 playbook procedures, remaining helpers and principle adaptations remain planned. A registry entry does not imply that its procedure was ported or evaluated.

T3 Code uses the user's saved jstack roles and live provider catalog instead of upstream model defaults and Cursor wrappers. The preflight calls the separately discovered setup-jstack resolver without copying it. That resolver selects a complete global or project configuration, with explicit selections taking precedence. Children receive the selected absolute path so their checkout cannot change routing. Inherited selections preserve the parent. Child briefs contain explicit context, fresh review rounds retain distinct task IDs, and the parent owns PR watches.

Activation until opt-out is a conversation instruction. Cursor mode frontmatter is not used as a portability or persistence mechanism. Resume and compaction remain separate evaluation requirements. T3 Code path-directed children do not acquire an app workspace binding from their prompt.

Publication, merging, installation and recurring work follow the user's authorized scope. Opening a PR is not an automatic ending for every task. Scoped evidence-based review replaces deletion-first comment rules; helper names do not require unrelated global skill installations.

## Shared investigation sources

The bundled [how](workflows/how.md) adapts [upstream how](https://github.com/cursor/plugins/tree/11713c683fe4add4fd403ea880580abbc9e0875f/pstack/skills/how), including its explorer and explainer prompts. It preserves the single-explainer simple path and two-to-four explorer complex path, followed by synthesis. Configured T3 roles replace fixed model defaults; failed resolution is reported rather than silently selecting another model.

The bundled [why](workflows/why.md) and [evidence contract](workflows/evidence.md) adapt [upstream why](https://github.com/cursor/plugins/tree/11713c683fe4add4fd403ea880580abbc9e0875f/pstack/skills/why), its investigator/synthesizer prompts, epistemics, source-category map, code archaeology and incident guidance. The five confidence levels and seven evidence categories remain. Search scope uses actual project relevance and authorization rather than assuming every connected service contains relevant records. Git history and forge access are checked separately. Provider-specific source playbooks are replaced by category briefs using live read-tool schemas. Read-only investigation scope permits owned temporary findings but does not assume a particular provider mode, write permission or global helper installation.
